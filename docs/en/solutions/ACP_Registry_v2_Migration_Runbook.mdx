# ACP Registry v2 Migration Runbook

This runbook migrates one ACP business cluster from the legacy chart Registry to Registry v2, managed by `cluster-image-registry-operator`. The standalone `registry-migrate` tool imports metadata while Registry v2 reuses the same S3 bucket, endpoint, and prefix.

The commands do not directly delete images or run GC. P5 removes the legacy chart resources and its leftover Ingress; the `ac delete images` calls in P8 are dry runs. Never add `--confirm`. P8 also restores the recorded Pruner suspension state: if that state is `false`, scheduled image cleanup can resume. Confirm that behavior before approving the cutover.

## Stage overview

| Stage | Purpose | Service interruption | Retry after failure |
| --- | --- | --- | --- |
| 0 | Validate tools, credentials, and the business cluster context | No | Yes |
| P0 plan | Generate and review the read-only plan | No | Yes |
| P1-backup | Save resource identities and prepare recovery material | No | Yes |
| P1-credentials | Hand off pull Secrets in place | No | Yes |
| P2-stop-writers | Stop legacy writers (**maintenance window starts**) | **Yes** | Yes |
| P3-final-inventory | Freeze the image inventory and S3 object listing | **Yes** | Yes; a recorded protection choice is immutable |
| P4-prepare-operator | Hold the Operator at zero replicas and prepare read-only Config | **Yes** | Yes |
| P5-remove-legacy-chart | Uninstall the legacy plugin, then remove its leftover Ingress | **Yes** | Retry checks; do not repeat a completed uninstall |
| P6-cold-import | Import metadata and namespace limits | **Yes** | Yes |
| P7-verify | Resume the Operator and verify read-only service | Read access restored | Yes |
| P8-commit | Verify business access and open writes (**maintenance window ends**) | Restored | Inspect the recorded and live state first |

Use the same run directory for retries. Start at section 0.

## Prerequisites

- **Tools and recovery procedures**: contact your ACP service provider for approved `registry-migrate` and compatible `ac` binaries, the Registry v2 bundle, and the platform pause and S3 recovery procedures.
- **Namespaces**: the default Operator installation namespace is `image-registry-system`; the default Registry operand namespace is `cpaas-system`. The operand namespace is fixed at installation. Confirm the actual values and use `scope.operandNamespace` in `plan.json` throughout the migration.
- **Storage scope**: stop if the legacy Registry's image-data backend uses PVCs or HostPath, or the migration contains non-image OCI artifacts or a non-default S3 root/prefix, unless the provider has approved another procedure. HostPath mounts used only by node trust or resolver components are not image-data storage.
- **Operator pause**: the Operator must remain at zero replicas during P4–P6. Manual InstallPlan approval does not pause an already running Operator. Establish the provider-approved pause before P4 and before removing the legacy chart.
- **CLI compatibility**: `AC_IMAGE_REGISTRY_MODE=legacy/modern` selects the mode, but an explicit `--registry-url` can keep requests on the Registry HTTP compatibility path. `AC_REGISTRY_COMPAT_OUTPUT` selects the output contract; leave it unset or set it to `4.3` for these checks.

## 0. Prepare the terminal and tools

Use one dedicated **Bash** terminal for all migration steps; do not enable `set -u` in an interactive zsh session. Login-token lifetime depends on the platform identity provider. If requests return `Unauthorized`, refresh the login associated with the kubeconfig used for migration. List the available sessions first:

```bash
ac config get-sessions
```

The row marked `*` in `CURRENT` is the active session. Use its `PLATFORM` and `SESSION` values to log in again:

```bash
printf 'PLATFORM: '; IFS= read -r PLATFORM
printf 'SESSION: '; IFS= read -r SESSION
ac login "$PLATFORM" --name "$SESSION"
```

The block below validates tools and credentials and selects a context. For a separate business kubeconfig, add `--kubeconfig /absolute/path/to/business.kubeconfig` to the login command above and use the same path in the block's `export KCFG=` line. Setup clears earlier `KCFG` values; login to the default file does not refresh a separate copy.

```bash
setup_run() {
umask 077
unset KCFG                      # clear a stale path left over from an earlier terminal
export KCFG="$HOME/.kube/config"
test -f "$KCFG" || { echo "ERROR: kubeconfig not found: $KCFG" >&2; echo "Edit the KCFG line above if the business kubeconfig is elsewhere" >&2; return 1; }
for b in registry-migrate ac jq curl; do
  command -v "$b" >/dev/null || { echo "ERROR: $b not found in PATH" >&2; return 1; }
done
printf 'Enter the real platform administrator account: '
IFS= read -r ACTOR
test -n "$ACTOR" || { echo "ERROR: administrator account is required" >&2; return 1; }
export REGISTRY_NS="cpaas-system"        # used to create the plan on a first run; overridden by plan.json on re-runs
export OPERATOR_NS="image-registry-system"
CTX_LIST="$(ac --kubeconfig "$KCFG" config get-contexts -o name || true)"
test -n "$CTX_LIST" || { echo "ERROR: no context in $KCFG" >&2; echo "Login first: ac login --platform <PLATFORM> --name <SESSION>" >&2; return 1; }
CTX="$(ac --kubeconfig "$KCFG" config current-context 2>/dev/null || true)"
test -n "$CTX" || { test "$(echo "$CTX_LIST" | grep -c .)" -eq 1 && CTX="$CTX_LIST" || {
  echo "Available contexts:" >&2; echo "$CTX_LIST" >&2; printf 'Enter the context to use: ' >&2; IFS= read -r CTX; }; }
echo "$CTX_LIST" | grep -Fxq "$CTX" || { echo "ERROR: context not found: $CTX" >&2; return 1; }
ac --kubeconfig "$KCFG" --context "$CTX" whoami >/dev/null 2>&1 || {
  echo "ERROR: not authenticated for context $CTX (token expired?)" >&2
  echo "Existing sessions:" >&2
  ac --kubeconfig "$KCFG" config get-sessions >&2 || true
  echo "Re-login: ac login --platform <PLATFORM> --name <SESSION>" >&2
  return 1; }
OUT="$PWD/registry-migrate-runs"
if test -n "${RUN_DIR:-}" && ! test -f "$RUN_DIR/plan.json"; then
  echo "WARN: ignoring stale RUN_DIR (no plan.json): $RUN_DIR" >&2
  unset RUN_DIR
fi
if test -n "${RUN_DIR:-}"; then
  test -f "$RUN_DIR/plan.json" || { echo "ERROR: RUN_DIR is set but plan.json is missing: $RUN_DIR" >&2; echo "Fix: unset RUN_DIR to start a new migration" >&2; return 1; }
  RUN_ID="$(jq -er '.runID' "$RUN_DIR/plan.json")"
  REGISTRY_NS="$(jq -er '.scope.operandNamespace' "$RUN_DIR/plan.json")"
  OPERATOR_NS="$(jq -er '.scope.operatorNamespace' "$RUN_DIR/plan.json")"
  REGISTRY_SERVICE="$(jq -er '.scope.serviceName' "$RUN_DIR/plan.json")"
  REGISTRY_DEPLOY="$(jq -r '.discovery.deployment // empty' "$RUN_DIR/plan.json")"
  GATEWAY_DEPLOY="$(jq -r '.discovery.gatewayDeployment // empty' "$RUN_DIR/plan.json")"
  OUT="$(dirname "$RUN_DIR")"
else
  RUN_ID="$(date -u +%Y%m%dT%H%M%SZ)-business-$RANDOM"
  RUN_DIR="$OUT/$RUN_ID"
fi
mkdir -p "$OUT"
S3_ARGS=()
FORCE_ARGS=()
registry-migrate version
ac version --client
printf 'context=%s\nrun-dir=%s\n' "$CTX" "$RUN_DIR"
}
setup_run || echo "STOP: section 0 aborted; fix the error above and re-run this block. The shell stays open." >&2
```

Confirm that `context=` identifies the intended business cluster. Before P0, select it with `ac --kubeconfig "$KCFG" config use-context "$CTX"`: the `ac` helpers use `CTX`, but `registry-migrate` uses the file's `current-context`.

Setup creates `OUT`; successful P0 creates `$RUN_DIR`. For retries, restore the original absolute `RUN_DIR` (appendix B), then reselect the required S3, force, nested-repository and P3 protection options. Do not discard a valid plan to bypass a failure.

The next block defines mandatory helpers. An error, timeout, or `STOP` message means the step needs attention even if the shell remains open or a later command prints output. Confirm the stage's success check before entering the next section.

```bash
acn() {
  test -n "${CTX:-}" || { echo "ERROR: CTX is empty; run section 0 first" >&2; return 1; }
  ac --kubeconfig "${KCFG:-$HOME/.kube/config}" --context "$CTX" "$@"
}
acns() { acn -n "$REGISTRY_NS" "$@"; }
evidence() {
  jq --arg actor "$ACTOR" --arg at "$(date -u +%Y-%m-%dT%H:%M:%SZ)" --arg field "$2" \
    '{version:"v1",runID:.runID,planDigest:.digest,observedAt:$at,actor:$actor,($field):true}' \
    "$RUN_DIR/plan.json" > "$RUN_DIR/$1"
}
stop_deployment() {
  local namespace="$1" name="$2" selector pods
  acn -n "$namespace" get deployment "$name" -o wide
  selector="$(acn -n "$namespace" get deployment "$name" -o json |
    jq -er '.spec.selector.matchLabels | to_entries | map("\(.key)=\(.value)") | join(",") | select(length > 0)')"
  acn -n "$namespace" scale deployment "$name" --replicas=0
  pods="$(acn -n "$namespace" get pods -l "$selector" -o name)"
  if test -n "$pods"; then
    acn -n "$namespace" wait --for=delete pod -l "$selector" --timeout=180s || true
  fi
}
```

## 1. P0: create and review the plan

```bash
registry-migrate plan --output-dir "$OUT" --run-id "$RUN_ID" \
  --operand-namespace "$REGISTRY_NS" --operator-namespace "$OPERATOR_NS" \
  --kubeconfig "$KCFG" &&
jq -e '(.discovery.blockers // []) | length == 0' "$RUN_DIR/plan.json" &&
REGISTRY_DEPLOY="$(jq -er '.discovery.deployment | select(length > 0)' "$RUN_DIR/plan.json")" &&
GATEWAY_DEPLOY="$(jq -er '.discovery.gatewayDeployment | select(length > 0)' "$RUN_DIR/plan.json")" &&
REGISTRY_SERVICE="$(jq -er '.scope.serviceName' "$RUN_DIR/plan.json")" &&
jq '{scope,storage:.discovery.storage,routes:.discovery.routes,limits:.namespaceLimits,warnings:.discovery.warnings}' "$RUN_DIR/plan.json" &&
echo "P0 OK: $RUN_DIR/plan.json"
```

`P0 OK` means the plan was generated and the blocker check passed. If it is absent, stay at P0 and inspect the error or blockers:

```bash
jq '.discovery.blockers' "$RUN_DIR/plan.json"
```

Planning is read-only. Compare the scope, S3 bucket/endpoint/prefix, original host/TLS/IngressClass, replica counts, scheduling, and timeouts with the change record and live cluster. Stop on any mismatch. If `scope.operandNamespace` is wrong, correct `REGISTRY_NS` in section 0 before planning again.

Check for pre-existing Registry v2 metadata before stopping writers. Legacy chart test images should be pushed to the legacy Registry; do not manually create backing ImageStream objects as migration test data. Existing metadata is a review condition, not a reason to delete it. Save the following list and inspect any objects in repositories covered by this migration:

```bash
check_existing_streams() {
  local crd
  crd="$(acn get crd imagestreams.storage.image.alauda.io --ignore-not-found -o name)" || return 1
  if test -z "$crd"; then
    echo "No Registry v2 backing ImageStream CRD exists yet."
    return 0
  fi
  acn get imagestreams.storage.image.alauda.io -A -o json \
    > "$RUN_DIR/existing-image-streams.json" || return 1
  jq -r '.items[] | [.metadata.namespace, .metadata.name, .metadata.uid,
    (.metadata.annotations["registry-migrate.run-id"] // "unowned"),
    (.metadata.annotations["registry-migrate.plan-digest"] // "")] | @tsv' \
    "$RUN_DIR/existing-image-streams.json"
}
check_existing_streams_or_stop() {
  check_existing_streams || {
    echo "STOP: existing ImageStream inventory failed; fix the error before stopping writers or continuing." >&2
    echo "Do not continue to P1 until the inventory file is complete." >&2
    return 1
  }
}
check_existing_streams_or_stop
```

## 2. P1-backup: save recovery material

Complete this stage **before P1-credentials**, which rewrites pull Secret contents in place. The tool creates a redacted Registry-scoped snapshot of resource identities, owners, ServiceAccounts, references, and data digests. It contains **neither Secret data nor S3 image data**.

Separately preserve chart versions/values, platform objects and protected Secret data through the approved recovery procedure. Keep them private and outside the redacted backup. Recreating a Secret or ServiceAccount cannot restore its UID. Confirm recovery and retention arrangements before chart removal.

```bash
registry-migrate backup --run-dir "$RUN_DIR" --kubeconfig "$KCFG" --approve
```

Success check: the command exits 0 and writes the resource and Secret summaries under `$RUN_DIR`. On failure, resolve the reported error and retry P1-backup before continuing.

## 3. P1-credentials: hand off pull Secrets

Keep the legacy Registry readable. First pause the platform source managing `sa-imagepullsecret-controller` so it cannot restart the controller. If discovery reports multiple candidates, use `acn get deployments -A -o wide | grep -i imagepull` to identify the intended controller before proceeding.

```bash
PULL_SECRET_REF="$(acn get deployments -A -o json | jq -er '
  [.items[] | select((.metadata.name | test("sa-imagepullsecret-controller";"i")) or
    ((.metadata.labels // {}) | tojson | test("sa-imagepullsecret-controller";"i"))) |
    [.metadata.namespace,.metadata.name]] |
  if length == 1 then .[0] | @tsv else error("review legacy pull-secret controller candidates") end')"
PULL_SECRET_NS=""; PULL_SECRET_DEPLOY=""
IFS=$'\t' read -r PULL_SECRET_NS PULL_SECRET_DEPLOY <<< "$PULL_SECRET_REF"
if test -z "$PULL_SECRET_DEPLOY"; then
  echo "STOP: cannot resolve the legacy pull-secret controller; fix the jq error above and re-run. Stage not recorded." >&2
else
  if test "${#FORCE_ARGS[@]}" -eq 0; then
    stop_deployment "$PULL_SECRET_NS" "$PULL_SECRET_DEPLOY"
  else
    acn -n "$PULL_SECRET_NS" get deployment "$PULL_SECRET_DEPLOY" -o wide
    echo "force mode: leaving the legacy pull-secret controller state unchanged"
  fi
  evidence controller-stopped.json legacyControllerStopped
  registry-migrate run --run-dir "$RUN_DIR" --stage P1-credentials \
    --evidence-file "$RUN_DIR/controller-stopped.json" \
    "${FORCE_ARGS[@]}" --kubeconfig "$KCFG" --approve
fi
```

Success check: the tool reports the Secret count and `updated/skipped` counters and records the stage in the journal. Existing Secret names/UIDs and their ServiceAccount owner UIDs remain unchanged. In the normal path, verify the old controller is stopped before treating its stop evidence as valid. Do not uninstall the legacy chart yet.

## 4. P2-stop-writers: stop the legacy writers (maintenance window starts)

Pause the platform source managing the legacy chart. Stop the Registry and Gateway Deployments, suspend the legacy Pruner CronJob if present, and stop external jobs or metadata writers using the same S3 bucket/prefix. Suspending a CronJob does not stop an already active Job.

Before running the block, set `WRITER_RECORD` to the maintenance/change record naming those writers, their stop times, and administrator approval. If the file is absent or empty, this block returns before stopping components.

```bash
stop_writers() {
export WRITER_RECORD="${WRITER_RECORD:-/tmp/maintenance-writer-record.txt}"
if ! test -s "$WRITER_RECORD"; then
  echo "STOP: WRITER_RECORD missing or empty: $WRITER_RECORD; nothing was stopped." >&2
  echo "Create it first: window time, external writers, stop time, approver. The shell stays open." >&2
  return 1
fi
if test "${#FORCE_ARGS[@]}" -eq 0; then
  stop_deployment "$REGISTRY_NS" "$REGISTRY_DEPLOY"
  stop_deployment "$REGISTRY_NS" "$GATEWAY_DEPLOY"
else
  acns get deployment "$REGISTRY_DEPLOY" "$GATEWAY_DEPLOY" -o wide
  echo "force mode: leaving legacy Registry/Gateway states unchanged"
fi
LEGACY_PRUNER="$(acns get cronjob image-pruner --ignore-not-found -o name)"
if test -n "$LEGACY_PRUNER"; then
  if test "${#FORCE_ARGS[@]}" -eq 0; then
    acns patch cronjob image-pruner --type=merge -p '{"spec":{"suspend":true}}'
  else
    echo "force mode: leaving the legacy Pruner state unchanged"
  fi
fi
acns get endpoints "$REGISTRY_SERVICE" -o wide
acns get endpointslices.discovery.k8s.io -l "kubernetes.io/service-name=$REGISTRY_SERVICE" -o wide
mkdir -p "$RUN_DIR/verification"
acn get cronjob,job -A -o wide > "$RUN_DIR/verification/legacy-jobs.txt" ||
  echo "WARN: could not list cluster jobs" >&2
if test "$WRITER_RECORD" != "$RUN_DIR/writer-record.txt"; then
  cp "$WRITER_RECORD" "$RUN_DIR/writer-record.txt"
fi
evidence writers-stopped.json legacyWritersStopped
registry-migrate run --run-dir "$RUN_DIR" --stage P2-stop-writers \
  --evidence-file "$RUN_DIR/writers-stopped.json" \
  "${FORCE_ARGS[@]}" --kubeconfig "$KCFG" --approve
}
stop_writers
```

Normal-path success check: the old Registry/Gateway Pods and Ready endpoints are gone, the Pruner is suspended, relevant active Jobs have finished, and the stage is recorded. Review `verification/legacy-jobs.txt` for jobs affecting this Registry; unrelated platform jobs are outside this migration. If the listing fails, resolve that failure before P3.

Confirm external writers against `WRITER_RECORD`. Two unchanged S3 listings are only supporting observations: equal object counts and latest `LastModified` values do not prove that all writers are stopped or rule out overwrites.

If the platform cannot hold old components stopped, use `FORCE_ARGS=(--force)` only after the administrator accepts the consistency risk. Record their actual state and the tool's force warning; do not claim those Pods or endpoints are absent. See appendix B.

## 5. P3-final-inventory: freeze the inventory and S3 state

The final inventory records repository/tag/digest relationships and manifest/config metadata. `s3-snapshot.json` is an object-listing snapshot with counts, bytes, and a listing digest; **it is not a backup of image contents**. Layers stay in the existing S3 bucket/prefix.

For a recovery point, use a storage snapshot or backup that has been tested for restore. Enabling S3 versioning alone is not verified recovery evidence. If no recovery point is available, choose the explicit skip path and retain its warning.

Once P3 succeeds, its inventory and protection state are frozen. Adding proof later does not change a run that skipped verification. Before starting, choose exactly one of the following paths; running both assigns the last choice, so do not execute both.

**Path 1: explicitly skip recovery verification.** The administrator accepts that no S3 recovery point has been established; the tool records a warning and `not-established`.

```bash
P3_PROTECTION=(--skip-s3-backup-verification)
```

**Path 2: provide a verified recovery point.** The tool records the verification assertion and reference; it does not perform the storage restore itself.

`RESTORE_REFERENCE` identifies an actual verified backup/snapshot or its restore-test report, for example `backup-registry-20261104-001` or `/secure/recovery/registry-restore-test.json`. The associated record should identify the source bucket/prefix, recovery time, and restore result. A bucket name or S3 URL is not a recovery-point reference.

```bash
printf 'Enter the verified S3 recovery-point identifier or report path: '
IFS= read -r RESTORE_REFERENCE
test -n "$RESTORE_REFERENCE"
jq --arg actor "$ACTOR" --arg at "$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
  --arg ref "$RESTORE_REFERENCE" \
  '{version:"v1",runID:.runID,planDigest:.digest,observedAt:$at,actor:$actor,restoreVerified:true,restoreReference:$ref}' \
  "$RUN_DIR/plan.json" > "$RUN_DIR/restore-proof.json"
P3_PROTECTION=(--evidence-file "$RUN_DIR/restore-proof.json")
```

Nested repositories are not skipped by default. Use the option below only for administrator-approved historical test residue. Review every affected repository in `legacy-metadata-report.json`; do not use it to exclude live workloads just to pass the stage.

```bash
NESTED_ARGS=()
# NESTED_ARGS=(--skip-nested-repositories)
```

If P3 cannot resolve a cluster-internal S3 endpoint such as `*.svc.cluster.local`, establish the port forward and `S3_ARGS` in appendix A, then return here.

This example uses `resume`. In the current tool, `run` and `resume` execute the same selected-stage logic: an incomplete P3 can rescan S3 and metadata, with no pagination checkpoint. After P3 is recorded, retries validate its frozen artifacts rather than scanning the live source again.

```bash
registry-migrate resume --run-dir "$RUN_DIR" --stage P3-final-inventory \
  "${P3_PROTECTION[@]}" "${S3_ARGS[@]}" "${NESTED_ARGS[@]}" \
  "${FORCE_ARGS[@]}" --kubeconfig "$KCFG" --approve

registry-migrate report --run-dir "$RUN_DIR"

jq '{items:(.items|length),digest,sample:(.items[0] // {} | {namespace,repository,tag})}' "$RUN_DIR/final-inventory.json"
```

Success check: P3 is recorded and `final-inventory.json` and `s3-snapshot.json` are present. The scan reads tag links, manifests, and configs without copying layers.

Before retrying an incomplete P3 with `NESTED_ARGS=(--skip-nested-repositories)`, approve each affected repository in the report. Excluded tags are not imported. Do not edit a successful P3's inventory to add them; use a newly approved migration run.

## 6. P4-prepare-operator: prepare the read-only Registry v2

Install or upgrade the provider-approved bundle/CRD through the ACP Operator installation workflow. Keep the Operator at zero replicas during P4–P6 using the verified pause procedure; a Manual Subscription alone is insufficient. The tool prepares Config and credentials here; the Registry workloads are reconciled after resuming the Operator in P7.

Record the original Operator replica count for P7, separately from the planned Registry count. P8 restores the Pruner baseline; a new ImagePruner records `registry-migrate.original-suspend=false`, allowing scheduled cleanup. To keep cleanup disabled, arrange an approved suspended baseline before P4. Do not change the recorded annotation afterwards.

```bash
prepare_operator() {
acn -n "$OPERATOR_NS" get subscription,installplan,csv -o wide
stop_deployment "$OPERATOR_NS" cluster-image-registry-operator
PRUNER="$(acn get imagepruner.imageregistry.operator.alauda.io cluster --ignore-not-found -o name)"
if test -n "$PRUNER"; then
  acn get "$PRUNER" -o json > "$RUN_DIR/imagepruner-before.json"
  jq '{annotations:.metadata.annotations,suspend:.spec.suspend}' "$RUN_DIR/imagepruner-before.json"
  existing_run="$(jq -r '.metadata.annotations["registry-migrate.run-id"] // empty' "$RUN_DIR/imagepruner-before.json")"
  existing_plan="$(jq -r '.metadata.annotations["registry-migrate.plan-digest"] // empty' "$RUN_DIR/imagepruner-before.json")"
  current_run="$(jq -er '.runID' "$RUN_DIR/plan.json")"
  current_plan="$(jq -er '.digest' "$RUN_DIR/plan.json")"
  if test -n "$existing_run" && test "$existing_run" != "$current_run"; then
    echo "STOP: imagepruner belongs to run $existing_run; refusing to reuse it" >&2
    return 1
  fi
  if test -n "$existing_plan" && test "$existing_plan" != "$current_plan"; then
    echo "STOP: imagepruner was prepared by a different plan ($existing_plan)" >&2
    return 1
  fi
  if test -z "$existing_run"; then
    acn annotate "$PRUNER" "registry-migrate.run-id=$current_run"
  fi
  if test -z "$existing_plan"; then
    acn annotate "$PRUNER" "registry-migrate.plan-digest=$current_plan"
  fi
fi
evidence operator-paused.json operatorPaused
registry-migrate run --run-dir "$RUN_DIR" --stage P4-prepare-operator \
  --evidence-file "$RUN_DIR/operator-paused.json" \
  "${FORCE_ARGS[@]}" --kubeconfig "$KCFG" --approve
acn get config.imageregistry.operator.alauda.io cluster -o json |
  jq -e '.spec.readOnly == true and
    .spec.imagePullSecret.managementState == "Unmanaged" and
    .spec.storage.managementState == "Unmanaged"'
acn get imagepruner.imageregistry.operator.alauda.io cluster -o json |
  jq -e '.spec.suspend == true'
}
prepare_operator
```

Success check: the report shows `prepared`; Config has the planned S3 settings/routes, `readOnly=true`, and pull Secret/storage management both `Unmanaged`. The Pruner is suspended. `Unmanaged` storage leaves S3 lifecycle management with the administrator; it does not disconnect Registry from S3 or prohibit GC.

Stop if an ImagePruner belongs to another run/plan; resolve ownership with the provider. Preserve `registry-migrate.original-suspend` for P8. After an assertion failure, check the live Config, CRD version and pause state before retrying.

## 7. P5-remove-legacy-chart: uninstall the legacy chart

Uninstalling the chart removes its workloads; the tool cannot reinstall them automatically. First capture the pre-uninstall Secret list below. Keep this original baseline when retrying after an uninstall; capturing it afterwards would hide losses.

```bash
date -u > "$RUN_DIR/pre-uninstall-secrets.at"
acns get secret -o name > "$RUN_DIR/pre-uninstall-secrets.txt"
```

Before uninstalling, confirm the platform's retention procedure protects the original business pull Secrets/ServiceAccounts, planned Ingress TLS Secrets, and P4 target S3 credentials. The P4 target Secret is `image-registry-private-configuration-user`; retain its UID and data. A differently named legacy source S3 Secret may retire with the chart once the P4 target checkpoint is established.

The administrator then uninstalls the legacy Registry/Gateway plugin through the cluster plugin page. Chart-owned Secrets may be deleted with the chart, so check immediately afterwards:

```bash
test -s "$RUN_DIR/pre-uninstall-secrets.txt" ||
  echo "STOP: pre-uninstall snapshot missing; the diff below proves nothing" >&2
printf 'baseline captured at: %s\n' "$(cat "$RUN_DIR/pre-uninstall-secrets.at" 2>/dev/null || echo unknown)"
acns get secret -o name > "$RUN_DIR/post-uninstall-secrets.txt"
diff "$RUN_DIR/pre-uninstall-secrets.txt" "$RUN_DIR/post-uninstall-secrets.txt" ||
  echo "WARN: Secret list changed; confirm the TLS Secret and S3 credentials still exist before continuing" >&2
```

Treat the name-only diff as an initial loss check. Compare required UIDs with plan/P1 records and P4's credential checkpoint. Stop if a required Secret/ServiceAccount is missing or recreated, or target S3 credentials changed; use protected recovery material. Recreating a name does not restore its UID.

Once retention checks pass, remove the leftover Ingress and record P5. The next block deletes the plan's `gateway=true` Ingresses after comparing their UIDs; retain the route backup before running it.

```bash
remove_legacy_chart() {
acn -n "$OPERATOR_NS" get deployment cluster-image-registry-operator -o json |
  jq -e '.spec.replicas == 0' >/dev/null ||
  echo "WARN: operator replicas is not 0; confirm it is still paused before removing the legacy chart" >&2
ROUTE_COUNT="$(jq -e '[.discovery.routes[] | select(.gateway == true)] | length' "$RUN_DIR/plan.json")" ||
  { echo "STOP: cannot read routes from plan.json" >&2; return 1; }
test "$ROUTE_COUNT" -gt 0 ||
  echo "WARN: plan has no gateway route; confirm no legacy Ingress remains before recording the stage" >&2
FAILED=""
while IFS=$'\t' read -r name expected_uid; do
  actual_uid="$(acns get ingress "$name" --ignore-not-found -o jsonpath='{.metadata.uid}')"
  if test -z "$actual_uid"; then
    echo "SKIP: ingress $name is already absent"
    continue
  fi
  if test "$actual_uid" != "$expected_uid"; then
    echo "STOP: ingress $name has a different UID ($actual_uid != $expected_uid); not deleting" >&2
    FAILED=1
    continue
  fi
  acns delete ingress "$name" --wait=true
done < <(jq -r '.discovery.routes[] | select(.gateway == true) | [.name,.ingressUID] | @tsv' "$RUN_DIR/plan.json")
test -z "$FAILED" || { echo "STOP: legacy Ingress cleanup incomplete; stage not recorded. Shell stays open." >&2; return 1; }
registry-migrate run --run-dir "$RUN_DIR" --stage P5-remove-legacy-chart \
  --kubeconfig "$KCFG" --approve
}
remove_legacy_chart
```

Success check: P5 is recorded; old Service/Deployments/routes are gone, planned TLS Secrets remain, and business Secret/ServiceAccount identities are unchanged. Stop on a UID mismatch and consult the provider. New Ingresses use `targetName`; old names are cleanup targets only.

Use the provider-approved `registry-migrate` build with pre-existing ImageStream checks. P6 checks all target streams before its first metadata write. A matching digest alone is insufficient: the repository, source and Registry address must also match the frozen inventory and planned addresses. Equivalent pre-existing objects are reused without changing their UID or ownership. Known internal and external addresses do not require rewriting tag history.

Keep the new Operator paused. Confirm zero replicas and no Operator Pods, then generate fresh pause evidence and import:

Success check: the report shows `imported`, with progress for unique ImageDigest objects, ImageStream/tag relationships, and namespace limits. A shared digest is stored once while preserving its repository/tag references. Retry failures in the same run with the Operator still paused; section 9 checks the result.

If preflight reports a digest/source conflict or an existing stream that needs changes but is not owned by this migration, stop and resolve it against `final-inventory.json` and the saved ImageStream snapshot. The tool leaves the object unchanged. Do not add `registry-migrate.run-id` or `registry-migrate.plan-digest` manually: annotations written outside the tool journal have no rollback record and can block later runs. A provider-approved journaled adoption procedure must separately validate UID/resourceVersion and the repository/tag/digest mapping. A same-digest object that needs no change is reused automatically. Neither `--force` nor deleting the inventory/journal resolves metadata conflicts. Keep any ImageDigest objects from a partial earlier attempt; P6 reuses matching records.

After an approved, journaled adoption procedure, rerun the original P6 command with fresh pause evidence. The tool pins eligible DockerImage tag sources to the verified digest and preserves existing history; real digest conflicts remain errors. The old Gateway limits become each planned namespace's `registry-migrate-image-limits` LimitRange: image size uses `type: alauda.io/Image` with `max.storage`; tag count uses `type: alauda.io/ImageStream` with `max["alauda.io/repository-tags"]`. Legacy `2GB/2000` becomes `2Gi/2000` (`2Gi=2048Mi`). **2000 is the tag limit for each repository/ImageStream in that namespace, not the namespace-wide total.** The plan selects namespace-specific rules. Migration does not overwrite user-defined limits or apply policy to future namespaces.

## 10. P8-commit: verify business access, then open writes

`REGISTRY_URL` must reach the new Registry through the original external entry point. The default below combines the plan's `scheme` and `hostname`; it **does not supply an external port** and may not reflect upstream TLS termination. Before running the block, set `REGISTRY_URL_OVERRIDE` to the actual full URL when needed, for example `https://registry.example.com:11780`. Confirm any alternate domain/VIP serves this Registry; do not reuse another environment's port.

For TLS, the issuer must be trusted and the SAN must match the host. For a private CA, set `REGISTRY_CA_BUNDLE` to its PEM file; the block supplies it to curl and exports `SSL_CERT_FILE` for `ac`. Correct any certificate/address mismatch. `REGISTRY_TLS_INSECURE=1` is diagnostic only and does not establish TLS acceptance.

`TEST_NS` and `TEST_REPO` default to the first inventory entry, which is not necessarily a disposable test target. Set them to an approved migrated test image before the block. Both delete calls must remain dry runs; never add confirmation flags.

```bash
export REGISTRY_HOST="$(jq -er '([.discovery.routes[] | select(.gateway == true)][0] // .discovery.routes[0]).hostname' "$RUN_DIR/plan.json")"
REGISTRY_SCHEME="$(jq -er '([.discovery.routes[] | select(.gateway == true)][0] // .discovery.routes[0]).scheme // "http"' "$RUN_DIR/plan.json")"
unset REGISTRY_URL
export REGISTRY_URL="${REGISTRY_URL_OVERRIDE:-$REGISTRY_SCHEME://$REGISTRY_HOST}"
printf 'REGISTRY_URL=%s\n' "$REGISTRY_URL"
jq -ne --arg url "$REGISTRY_URL" --arg host "$REGISTRY_HOST" \
  '($url | capture("^https?://(?<host>[^/:]+)(:[0-9]+)?/?$").host) == $host' >/dev/null 2>&1 ||
  echo "NOTE: REGISTRY_URL is not the bare planned ingress host ($REGISTRY_HOST); confirm it is the external address of the new Registry."
mkdir -p "$RUN_DIR/verification"
CURL_TLS_ARGS=()
AC_TLS_ARGS=()
if test -n "${REGISTRY_CA_BUNDLE:-}"; then
  CURL_TLS_ARGS+=(--cacert "$REGISTRY_CA_BUNDLE")
  export SSL_CERT_FILE="$REGISTRY_CA_BUNDLE"
fi
if test "${REGISTRY_TLS_INSECURE:-0}" = 1; then
  CURL_TLS_ARGS+=(--insecure)
  AC_TLS_ARGS+=(--insecure-skip-tls-verify)
fi
probe_and_export() {
  http_code="$(curl -sS "${CURL_TLS_ARGS[@]}" --connect-timeout 10 --max-time 20 \
    -o /dev/null -w '%{http_code}' "$REGISTRY_URL/v2/")"
  case "$http_code" in
    200|401|403) echo "Registry reachable: HTTP $http_code" ;;
    *) echo "ERROR: unexpected HTTP ${http_code:-000} from $REGISTRY_URL/v2/" >&2
       echo "000 = this machine cannot reach the host (route/VPN/DNS); 502/504 = a proxy or the ingress cannot reach the backend." >&2
       echo "The shell stays open. Fix the cause, then re-run this block." >&2
       return 1 ;;
  esac
  curl -sS "${CURL_TLS_ARGS[@]}" --connect-timeout 10 --max-time 20 \
    -D "$RUN_DIR/verification/registry-v2-headers.txt" -o /dev/null "$REGISTRY_URL/v2/"
  if grep -qi '^WWW-Authenticate:' "$RUN_DIR/verification/registry-v2-headers.txt"; then
    echo "Check the host and port of the WWW-Authenticate realm; see appendix A if they differ from the ingress." >&2
  fi

  TEST_NS="${TEST_NS:-$(jq -er '.items[0].namespace' "$RUN_DIR/final-inventory.json")}" ||
    { echo "ERROR: final-inventory.json has no items; P3 produced no inventory" >&2; return 1; }
  TEST_REPO="${TEST_REPO:-$(jq -r '.items[0] | "\(.namespace)/\(.repository):\(.tag)"' "$RUN_DIR/final-inventory.json")}"
  export TEST_NS TEST_REPO

  env AC_IMAGE_REGISTRY_MODE=legacy \
    ac --kubeconfig "$KCFG" --context "$CTX" "${AC_TLS_ARGS[@]}" get images -n "$TEST_NS" -o json \
    --registry-url "$REGISTRY_URL" > "$RUN_DIR/verification/legacy-images.json" ||
    { echo "ERROR: legacy view failed; see the error above. The shell stays open." >&2; return 1; }
  env AC_IMAGE_REGISTRY_MODE=modern \
    ac --kubeconfig "$KCFG" --context "$CTX" "${AC_TLS_ARGS[@]}" get images -A -o json \
    --registry-url "$REGISTRY_URL" > "$RUN_DIR/verification/modern-images.json" ||
    { echo "ERROR: modern view failed; see the error above. The shell stays open." >&2; return 1; }
  printf 'legacy=%s modern=%s\n' \
    "$(jq '.items | length' "$RUN_DIR/verification/legacy-images.json" 2>/dev/null || echo n/a)" \
    "$(jq '.items | length' "$RUN_DIR/verification/modern-images.json" 2>/dev/null || echo n/a)"

  # Keep these as dry runs: never add --confirm / --yes / -f, or the tag is really deleted.
  env AC_IMAGE_REGISTRY_MODE=legacy \
    ac --kubeconfig "$KCFG" --context "$CTX" "${AC_TLS_ARGS[@]}" delete images \
    --repo "$TEST_REPO" --registry-url "$REGISTRY_URL"
  env AC_IMAGE_REGISTRY_MODE=modern \
    ac --kubeconfig "$KCFG" --context "$CTX" "${AC_TLS_ARGS[@]}" delete images \
    --repo "$TEST_REPO" --registry-url "$REGISTRY_URL"
}
probe_and_export
```

Success check: queries in both modes succeed, and both delete calls identify the intended tag without deleting it; dry-run wording varies by `ac` version. Both modes pass `--registry-url`, so these are HTTP compatibility checks, not independent public Image API checks; P7 covers that API. Anonymous `/v2/` 200/401/403 proves reachability only, and row counts do not prove completeness. A failed or timed-out query remains unverified even if a later command succeeds.

The next snippet is a **limited credential-format check**, not a complete audit of every namespace. It examines `.dockerconfigjson` Secrets only; legacy chart pull Secrets commonly use `.dockercfg` and must be checked separately against the P1 handoff records and original SA references. Other registries' credentials need not contain this Registry host.

```bash
acn get secret -A -o json |
  jq -r --arg h "$REGISTRY_HOST" '
    .items[] | select(.type == "kubernetes.io/dockerconfigjson") |
    (.data[".dockerconfigjson"] | @base64d | fromjson? | (.auths // {}) | keys) as $k |
    select(($k | any(test($h))) | not) |
    "REVIEW \(.metadata.namespace)/\(.metadata.name): no auth entry for \($h)"'
```

No output does not prove all pull Secrets were checked or that registry addresses match exactly: the snippet uses a regex, not an exact host/port comparison. Cross-check the P1 scope, legacy `.dockercfg` objects, each original image's registry address/port, and SA references. A `REVIEW` entry for another registry is not automatically a migration failure.

Before P8, pull Secret management is `Unmanaged`, so the Operator **does not rotate or repair these credentials automatically**. Resolve missing entries or invalid tokens before approving the handoff; do not wait for a background refresh.

Before committing, create a disposable Pod with `imagePullPolicy=Always`, using an approved migrated test image's **original address, ServiceAccount and pull Secret**. Verify actual kubelet pulls on the relevant business nodes and through each address/port used by the workload. Record the Pod, digest and pull result, then remove the test Pod. API queries or existing running Pods alone do not prove new pulls work.

Do not run `ac adm prune images` or GC during this procedure. They require platform-level authority and can remove data. Confirm the recorded Pruner suspension value and whether scheduled cleanup may resume after P8.

Run the next block only after those business and credential checks pass and an administrator approves opening writes with a controlled recovery plan. It directly asserts `businessProbeVerified` and `pullSecretHandoffVerified`; creating that evidence file is not the verification itself.

```bash
commit_run() {
test -n "${ACTOR:-}" || { echo "ERROR: ACTOR is empty; export ACTOR=<platform admin account> and re-run this block" >&2; return 1; }
jq --arg actor "$ACTOR" --arg at "$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
  '{version:"v1",runID:.runID,planDigest:.digest,observedAt:$at,actor:$actor,commitApproved:true,businessProbeVerified:true,pullSecretHandoffVerified:true}' \
  "$RUN_DIR/plan.json" > "$RUN_DIR/commit-approval.json"
jq -e '.actor | length > 0' "$RUN_DIR/commit-approval.json" >/dev/null ||
  { echo "ERROR: commit-approval.json has an empty actor; the tool rejects it" >&2; return 1; }
registry-migrate run --run-dir "$RUN_DIR" --stage P8-commit \
  --evidence-file "$RUN_DIR/commit-approval.json" --kubeconfig "$KCFG" --approve
acn get config.imageregistry.operator.alauda.io cluster -o json |
  jq -e '.spec.readOnly == false and
    .spec.imagePullSecret.managementState == "Managed" and
    .spec.storage.managementState == "Unmanaged"' ||
  echo "NOTE: the commit itself may have succeeded and only this Config assertion failed; check the state in registry-migrate report before considering rollback" >&2
acn get imagepruner.imageregistry.operator.alauda.io cluster -o json | jq -e '
  (.metadata.annotations["registry-migrate.original-suspend"] // "false") as $original |
```

Success check: the report shows `committed`; Config has `readOnly=false`, pull Secret management is `Managed`, and storage stays `Unmanaged`. The Pruner returns to `registry-migrate.original-suspend`; `false` permits scheduled cleanup to resume. Storage being `Unmanaged` does not prevent that cleanup.

A failing post-commit assertion does not establish that writes stayed closed. Check the journal and live state before recovery; account for new images and credential rotation after cutover. Finally, use an approved OCI client to push and pull one disposable repository and retain the output. Fix authentication-realm or TLS failures and repeat the client test; curl manifest/blob reads are diagnostic evidence, not a replacement for successful OCI or kubelet pulls.

## Appendix A: known environment limitations

### S3 reachable only from inside the cluster

If the plan's S3 endpoint is cluster-internal, this machine may fail to resolve it and P3 can stop with `dial tcp: lookup ... no such host`. Establish a port forward in **a second terminal**, where it remains in the foreground.

Set `KCFG` and `CTX` in that terminal to the exact values used by the migration terminal. Its environment is independent, and the default/current context may identify another cluster. If the kubeconfig has no `current-context`, explicitly supply the selected `CTX`. Replace `minio-system/service/minio` and the port with the actual S3 Service details:

```bash
: "${KCFG:=$HOME/.kube/config}"
: "${CTX:=$(ac --kubeconfig "$KCFG" config current-context)}"
ac --kubeconfig "$KCFG" --context "$CTX" -n minio-system port-forward service/minio 19000:9000
```

Back in the **migration terminal**, confirm that the tunnel works and set the override:

```bash
curl --fail --connect-timeout 5 --max-time 10 http://127.0.0.1:19000/minio/health/live
S3_ARGS=(--s3-endpoint http://127.0.0.1:19000)
```

This override changes only P3's transport address; the endpoint recorded in the plan/snapshot and target Config remains the source endpoint. Port forwarding does not convert HTTP to HTTPS. Reestablish a dropped tunnel and retry the same run.

### Authentication realm and ingress port disagree

The 401 response from `/v2/` may advertise a `WWW-Authenticate` realm with a port different from the externally reachable Ingress port, such as 443 instead of 11780. Registry data can remain readable while OCI authentication fails. Use the `REGISTRY_URL` defined in section 10 to inspect the challenge:

```bash
curl -sS -k -D - -o /dev/null "$REGISTRY_URL/v2/" | grep -i '^www-authenticate:'
```

Replace diagnostic `-k` with system trust or `--cacert /path/to/ca.pem` for verified TLS. If the realm is unreachable, diagnose it with curl, correct the entry-point configuration, and repeat OCI/kubelet pull checks. Record an entry-point failure separately from metadata integrity; a successful curl read does not establish full business acceptance.

## Appendix B: retries, exceptions, and recovery

### Continue the same run after the terminal exits

```bash
export RUN_DIR="/absolute/path/to/registry-migrate-runs/original-run-id"
# Re-set the arrays you need, as described in section 5 (skip the ones you do not use):
#   S3_ARGS=(--s3-endpoint http://127.0.0.1:19000)
#   FORCE_ARGS=(--force)
#   NESTED_ARGS=(--skip-nested-repositories)
```

Restore the original absolute `RUN_DIR`, run section 0 again, then reselect the required S3, force, nested-repository and P3 protection options; section 0 resets some arrays. `P3_PROTECTION` must match the recorded choice. Do not repeat a completed manual uninstall or capture a new post-uninstall baseline as if it were the original.

### Escape hatches

| Switch | When to use it | Effect |
| --- | --- | --- |
| `FORCE_ARGS=(--force)` | The administrator accepts relevant legacy components still running | Bypasses only the legacy writer fence; API, UID, S3, metadata, stage and P4/P6 Operator-pause checks remain. Record the force warning and actual running state. |
| `P3_PROTECTION=(--skip-s3-backup-verification)` | The administrator accepts no established S3 recovery point | Records a warning and `not-established`; proof added later cannot change a successful P3 in this run. |
| `NESTED_ARGS=(--skip-nested-repositories)` | Affected nested repositories are approved historical test residue | Records exclusions; excluded tags are not imported. Review them individually. |

The original 4.3 `ac` has no `set-registry-mode`. Use its explicit Registry URL, kubeconfig and context for legacy queries. The separate compatibility acceptance record covers its full permission/pagination matrix; do not treat a different client's success as proof for the original binary.

### Rollback

`rollback` records `rollback-requested` in the journal and prevents later stages from advancing in that run. **It does not perform a restore**: it does not reinstall the chart, recreate original UIDs, remove Registry v2 resources or restore S3 objects. Use the report and the following checklist for administrator-owned recovery:

```bash
registry-migrate rollback --run-dir "$RUN_DIR" --kubeconfig "$KCFG" --approve
registry-migrate report --run-dir "$RUN_DIR"
```

- **Before chart removal**: restore original replicas, platform/Pruner state and chart configuration using the change record; use the separately protected material for credential data. P1 summaries provide identity evidence, not Secret contents.
- **After chart removal**: stop new Registry writes and reconciliation first, then restore the chart/platform configuration, credentials and S3 access through the approved recovery procedure.
- **After P8**: also account for new images and token rotation. Do not reactivate the legacy S3 writer without coordinating the recovery boundary.
- **After recovery**: create a new run ID. Do not edit the old plan/journal to bypass identity drift.

The tool is idempotent within one run: completed work is skipped or revalidated. Preserve the plan, journal, backup summaries, inventory, snapshot, evidence, verification output and separate recovery material.
