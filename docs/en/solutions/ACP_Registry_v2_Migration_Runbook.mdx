# ACP Registry v2 Migration Runbook

This runbook upgrades one ACP business cluster from the legacy chart Registry to the Registry managed by `cluster-image-registry-operator`. The migration is performed by the independent `registry-migrate` tool; it is not an automatic takeover feature of the Operator.

Before the maintenance window, contact your ACP platform service provider and obtain the provider-approved `registry-migrate` binary, compatible `ac`, the Registry v2 Operator bundle/CRD, the ACP pause/hold procedure, and the S3 backup/restore procedure. This runbook was checked against `registry-migrate` v4.5.0 (commit `6edeb747`). The migration tool version is independent of the ACP release. Do not build binaries during the window.

This procedure covers one ACP cluster, one legacy Registry, the same business cluster, legacy S3 storage, and a Gateway Ingress as the external entry point. Registry v2 reuses the same S3 bucket, endpoint, and prefix. A legacy `image-registry` Service of type `NodePort` is acceptable when clients use the Gateway Ingress address.

PVC/filesystem migration, cross-cluster mirroring, `ac image mirror`, manual `ImageStreamMapping` backfill, and automatic Operator takeover are outside this runbook. Migrate one cluster at a time. P2 starts the maintenance window; P7 restores read-only service; P8 opens writes.

## 0. Prepare the terminal and tools

Use a dedicated Bash terminal. `cpaas-system` and `image-registry-system` are common ACP namespaces; confirm them.

```bash
set -e -o pipefail
umask 077
export KCFG="/path/to/business.kubeconfig"
printf 'Enter the real platform administrator account: '
IFS= read -r ACTOR
test -n "$ACTOR"
export REGISTRY_NS="cpaas-system"
export OPERATOR_NS="image-registry-system"
CTX="$(ac --kubeconfig "$KCFG" config current-context)"
test -n "$CTX"
OUT="$PWD/registry-migrate-runs"

if test -n "$RUN_DIR"; then
  test -f "$RUN_DIR/plan.json"
  RUN_ID="$(jq -er '.runID' "$RUN_DIR/plan.json")"
  REGISTRY_NS="$(jq -er '.scope.operandNamespace' "$RUN_DIR/plan.json")"
  OPERATOR_NS="$(jq -er '.scope.operatorNamespace' "$RUN_DIR/plan.json")"
  REGISTRY_SERVICE="$(jq -er '.scope.serviceName' "$RUN_DIR/plan.json")"
  REGISTRY_DEPLOY="$(jq -r '.discovery.deployment // empty' "$RUN_DIR/plan.json")"
  GATEWAY_DEPLOY="$(jq -r '.discovery.gatewayDeployment // empty' "$RUN_DIR/plan.json")"
  OUT="$(dirname "$RUN_DIR")"
else
  RUN_ID="$(date -u +%Y%m%dT%H%M%SZ)-business-$RANDOM"
  RUN_DIR="$OUT/$RUN_ID"
fi
mkdir -p "$OUT"
S3_ARGS=()
FORCE_ARGS=()
NESTED_ARGS=()
registry-migrate version
ac version --client
printf 'context=%s\nrun-dir=%s\n' "$CTX" "$RUN_DIR"

acn() { ac --kubeconfig "$KCFG" --context "$CTX" "$@"; }
acns() { acn -n "$REGISTRY_NS" "$@"; }
evidence() {
  jq --arg actor "$ACTOR" --arg at "$(date -u +%Y-%m-%dT%H:%M:%SZ)" --arg field "$2" \
    '{version:"v1",runID:.runID,planDigest:.digest,observedAt:$at,actor:$actor,($field):true}' \
    "$RUN_DIR/plan.json" > "$RUN_DIR/$1"
}
stop_deployment() {
  local namespace="$1" name="$2" selector
  acn -n "$namespace" get deployment "$name" -o wide
  selector="$(acn -n "$namespace" get deployment "$name" -o json |
    jq -er '.spec.selector.matchLabels | to_entries | map("\(.key)=\(.value)") | join(",") | select(length > 0)')"
  acn -n "$namespace" scale deployment "$name" --replicas=0
  pods="$(acn -n "$namespace" get pods -l "$selector" -o name)"
  if test -n "$pods"; then
    acn -n "$namespace" wait --for=delete pod -l "$selector" --timeout=180s
  fi
}
```

For a new migration, unset `RUN_DIR` before this section. To recover after the terminal exits, export the original absolute `RUN_DIR` and run this section again; it restores the run ID, namespaces, and Deployment names from `plan.json`. Do not create a new run for a retry. Re-select S3 and force arrays after reload.

## 1. P0: create and review the plan

```bash
registry-migrate plan --output-dir "$OUT" --run-id "$RUN_ID" \
  --operand-namespace "$REGISTRY_NS" --operator-namespace "$OPERATOR_NS" \
  --kubeconfig "$KCFG"
jq -e '(.discovery.blockers // []) | length == 0' "$RUN_DIR/plan.json"
REGISTRY_DEPLOY="$(jq -er '.discovery.deployment | select(length > 0)' "$RUN_DIR/plan.json")"
GATEWAY_DEPLOY="$(jq -er '.discovery.gatewayDeployment | select(length > 0)' "$RUN_DIR/plan.json")"
REGISTRY_SERVICE="$(jq -er '.scope.serviceName' "$RUN_DIR/plan.json")"
jq '{scope,storage:.discovery.storage,routes:.discovery.routes,limits:.namespaceLimits,warnings:.discovery.warnings}' "$RUN_DIR/plan.json"
```

The plan is read-only. Review every blocker, S3 bucket/endpoint/prefix, old host/TLS/IngressClass, replicas, scheduling fields, and timeout values. Stop if any blocker is present or the plan does not match the cluster.

## 2. P1-backup: save recovery material

Save old chart values, platform management objects, protected credentials, and the provider’s S3 recovery record. The tool backup is a redacted Registry-scoped snapshot; it does not contain Secret data or restore S3 image data by itself.

```bash
registry-migrate backup --run-dir "$RUN_DIR" --kubeconfig "$KCFG" --approve
```

Expected result: a recorded stage and relevant resource/Secret summaries containing UID, owner, ServiceAccount, and reference information. This is not a backup of every object in the namespace.

## 3. P1-credentials: hand off pull Secrets

The legacy Registry must still be readable. First pause the AppRelease/ClusterPlugin or other platform source that manages `sa-imagepullsecret-controller`.

```bash
PULL_SECRET_REF="$(acn get deployments -A -o json | jq -er '
  [.items[] | select((.metadata.name | test("sa-imagepullsecret-controller";"i")) or
    ((.metadata.labels // {}) | tojson | test("sa-imagepullsecret-controller";"i"))) |
    [.metadata.namespace,.metadata.name]] |
  if length == 1 then .[0] | @tsv else error("review legacy pull-secret controller candidates") end')"
IFS=$'\t' read -r PULL_SECRET_NS PULL_SECRET_DEPLOY <<< "$PULL_SECRET_REF"
if test "${#FORCE_ARGS[@]}" -eq 0; then
  stop_deployment "$PULL_SECRET_NS" "$PULL_SECRET_DEPLOY"
else
  acn -n "$PULL_SECRET_NS" get deployment "$PULL_SECRET_DEPLOY" -o wide
  echo "force mode: leaving the legacy pull-secret controller state unchanged"
fi
evidence controller-stopped.json legacyControllerStopped
registry-migrate run --run-dir "$RUN_DIR" --stage P1-credentials \
  --evidence-file "$RUN_DIR/controller-stopped.json" \
  "${FORCE_ARGS[@]}" --kubeconfig "$KCFG" --approve
```

Expected result: Secret totals, progress, `updated/skipped`, and a recorded stage. Existing Secret names/UIDs and ServiceAccount owner UIDs remain unchanged. Do not recreate same-named Secrets. Do not uninstall the old chart until this phase succeeds.

## 4. P2-stop-writers: stop legacy writers

Pause the legacy chart management source. Stop the legacy Registry and Gateway Deployments, pause the legacy Pruner when present, and stop external jobs writing the same S3 bucket/prefix. An old Image API or another metadata writer must be stopped and recorded by an administrator.

Before running the command, set `WRITER_RECORD` to the maintenance/change record that lists the external S3 and metadata writers, the stop time, and the administrator approval. The file is copied into the run directory for audit.

```bash
export WRITER_RECORD="/path/to/maintenance-writer-record.txt"
if test "${#FORCE_ARGS[@]}" -eq 0; then
  stop_deployment "$REGISTRY_NS" "$REGISTRY_DEPLOY"
  stop_deployment "$REGISTRY_NS" "$GATEWAY_DEPLOY"
else
  acns get deployment "$REGISTRY_DEPLOY" "$GATEWAY_DEPLOY" -o wide
  echo "force mode: leaving legacy Registry/Gateway states unchanged"
fi
LEGACY_PRUNER="$(acns get cronjob image-pruner --ignore-not-found -o name)"
if test -n "$LEGACY_PRUNER"; then
  if test "${#FORCE_ARGS[@]}" -eq 0; then
    acns patch cronjob image-pruner --type=merge -p '{"spec":{"suspend":true}}'
  else
    echo "force mode: leaving the legacy Pruner state unchanged"
  fi
fi
acns get endpoints "$REGISTRY_SERVICE" -o wide
acns get endpointslices.discovery.k8s.io -l "kubernetes.io/service-name=$REGISTRY_SERVICE" -o wide
test -n "$WRITER_RECORD"
test -s "$WRITER_RECORD"
if test "$WRITER_RECORD" != "$RUN_DIR/writer-record.txt"; then
  cp "$WRITER_RECORD" "$RUN_DIR/writer-record.txt"
fi
evidence writers-stopped.json legacyWritersStopped
registry-migrate run --run-dir "$RUN_DIR" --stage P2-stop-writers \
  --evidence-file "$RUN_DIR/writers-stopped.json" \
  "${FORCE_ARGS[@]}" --kubeconfig "$KCFG" --approve
```

Expected result in the normal path: old Registry/Gateway Pods and Ready endpoints are gone, the old Pruner is suspended, active jobs have finished, and the stage is recorded. The copied `WRITER_RECORD` is a mandatory administrator gate for external writers; the tool separately checks live cluster writers. If the platform cannot keep old components stopped, set `FORCE_ARGS=(--force)` only after an administrator accepts the consistency risk; in that path, record the actual running state and expect the tool’s force-fence warning instead of claiming that the old Pods or endpoints are gone. Force does not bypass API, UID, S3, metadata, stage, or new Operator pause checks.

## 5. P3-final-inventory: freeze the inventory and S3 state

The final inventory records repository/tag/digest relationships and manifest/config metadata. The S3 snapshot records object count, bytes, and listing digest. It does not copy layers or provide data recovery.

Choose exactly one path.

**Verified recovery point:**

```bash
printf 'Enter the verified S3 recovery-point identifier or report path: '
IFS= read -r RESTORE_REFERENCE
test -n "$RESTORE_REFERENCE"
jq --arg actor "$ACTOR" --arg at "$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
  --arg ref "$RESTORE_REFERENCE" \
  '{version:"v1",runID:.runID,planDigest:.digest,observedAt:$at,actor:$actor,restoreVerified:true,restoreReference:$ref}' \
  "$RUN_DIR/plan.json" > "$RUN_DIR/restore-proof.json"
P3_PROTECTION=(--evidence-file "$RUN_DIR/restore-proof.json")
```

**Explicitly skipped recovery verification:** an administrator may accept a run with no S3 recovery point. The tool records a warning and `not-established` state.

```bash
P3_PROTECTION=(--skip-s3-backup-verification)
```

Do not use both paths.

```bash
registry-migrate resume --run-dir "$RUN_DIR" --stage P3-final-inventory \
  "${P3_PROTECTION[@]}" "${S3_ARGS[@]}" \
  "${NESTED_ARGS[@]}" \
  "${FORCE_ARGS[@]}" --kubeconfig "$KCFG" --approve
registry-migrate report --run-dir "$RUN_DIR"
jq '{items:(.items|length),digest,sample:(.items[0] | {namespace,repository,tag,digest})}' "$RUN_DIR/final-inventory.json"
```

Expected result: recorded stage, `final-inventory.json`, and `s3-snapshot.json`. Scanning reads tag links, manifests, and configs; it does not move layers. Approved test residue excluded with `--skip-nested-repositories` must be reviewed in `legacy-metadata-report.json` and not counted as migrated. Set `NESTED_ARGS=(--skip-nested-repositories)` before P3 only for that approved residue; the normal value is `NESTED_ARGS=()`.


## 6. P4-prepare-operator: prepare Registry v2 read-only

Install or upgrade the provider-approved Operator bundle/CRD. Establish the ACP-specific pause/hold that keeps the current Operator Deployment at zero during P4–P6. A Manual Subscription controls InstallPlan approval; it does not pause an already running Operator.

```bash
acn -n "$OPERATOR_NS" get subscription,installplan,csv -o wide
stop_deployment "$OPERATOR_NS" cluster-image-registry-operator
PRUNER="$(acn get imagepruner.imageregistry.operator.alauda.io cluster --ignore-not-found -o name)"
if test -n "$PRUNER"; then
  acn get "$PRUNER" -o json > "$RUN_DIR/imagepruner-before.json"
  jq '{annotations:.metadata.annotations,suspend:.spec.suspend}' "$RUN_DIR/imagepruner-before.json"
  existing_run="$(jq -r '.metadata.annotations["registry-migrate.run-id"] // empty' "$RUN_DIR/imagepruner-before.json")"
  existing_plan="$(jq -r '.metadata.annotations["registry-migrate.plan-digest"] // empty' "$RUN_DIR/imagepruner-before.json")"
  current_run="$(jq -er '.runID' "$RUN_DIR/plan.json")"
  current_plan="$(jq -er '.digest' "$RUN_DIR/plan.json")"
  test -z "$existing_run" -o "$existing_run" = "$current_run"
  test -z "$existing_plan" -o "$existing_plan" = "$current_plan"
  if test -z "$existing_run"; then
    acn annotate "$PRUNER" "registry-migrate.run-id=$current_run"
  fi
  if test -z "$existing_plan"; then
    acn annotate "$PRUNER" "registry-migrate.plan-digest=$current_plan"
  fi
fi
evidence operator-paused.json operatorPaused
registry-migrate run --run-dir "$RUN_DIR" --stage P4-prepare-operator \
  --evidence-file "$RUN_DIR/operator-paused.json" \
  "${FORCE_ARGS[@]}" --kubeconfig "$KCFG" --approve
acn get config.imageregistry.operator.alauda.io cluster -o json |
  jq -e '.spec.readOnly == true and .spec.imagePullSecret.managementState == "Unmanaged"'
acn get imagepruner.imageregistry.operator.alauda.io cluster -o json |
  jq -e '.spec.suspend == true'
```

Expected result: `state=prepared`; Config reuses planned S3/routes, is read-only, and leaves pull-Secret management Unmanaged. The Pruner is suspended. If it did not exist, the tool creates it and records `registry-migrate.original-suspend=false`. An annotation conflict is a stop condition; do not use `--overwrite`.

## 7. P5-remove-legacy-chart: uninstall the old chart

The platform administrator uninstalls the legacy Registry/Gateway chart through the actual AppRelease/ClusterPlugin process. The tool does not perform this uninstall. Keep business pull Secrets, ServiceAccounts, S3 data, and TLS Secrets.

```bash
jq -r '.discovery.routes[] | select(.gateway == true) | [.name,.ingressUID] | @tsv' "$RUN_DIR/plan.json" |
while IFS=$'\t' read -r name expected_uid; do
  actual_uid="$(acns get ingress "$name" --ignore-not-found -o jsonpath='{.metadata.uid}')"
  if test -n "$actual_uid"; then
    test "$actual_uid" = "$expected_uid"
    acns delete ingress "$name" --wait=true
  fi
done
registry-migrate run --run-dir "$RUN_DIR" --stage P5-remove-legacy-chart \
  --kubeconfig "$KCFG" --approve
```

Expected result: recorded stage. The tool confirms old Service/Deployments/routes are gone, TLS Secret remains, and business Secret/ServiceAccount identities have not changed. New Ingress uses planned `targetName` values; the old Ingress name is only a deletion target.

## 8. P6-cold-import: import metadata and limits

The new Operator must still be paused. Re-check the pause and generate a fresh evidence file before importing.

```bash
stop_deployment "$OPERATOR_NS" cluster-image-registry-operator
evidence operator-paused.json operatorPaused
registry-migrate run --run-dir "$RUN_DIR" --stage P6-cold-import \
  --inventory-file "$RUN_DIR/final-inventory.json" \
  --evidence-file "$RUN_DIR/operator-paused.json" \
  "${FORCE_ARGS[@]}" --kubeconfig "$KCFG" --approve
```

Expected result: `state=imported`, with progress for unique ImageDigest objects, ImageStream/tag relationships, and namespace limits. Shared digests are stored once while repository/tag references remain. No blobs or layers are uploaded and no ordinary `ImageStreamMapping` bypass is used.

The legacy Gateway limits are projected into existing namespace `registry-migrate-image-limits` LimitRange: `type: alauda.io/Image` with `max.storage` for image size, and `type: alauda.io/ImageStream` with `max["alauda.io/repository-tags"]` for repository-tag count. A legacy `2GB/2000` value is represented as `2Gi/2000`. Namespace-specific rules are selected by the approved plan; review `namespaceLimits` when rules overlap. The migration does not create ResourceQuota, overwrite existing user limits, or configure future namespaces.

## 9. P7-verify: resume the Operator and verify read-only service

Release the ACP pause/hold through the platform procedure. Then restore the Operator and wait for the data plane.

```bash
acn -n "$OPERATOR_NS" scale deployment cluster-image-registry-operator --replicas=1
acn -n "$OPERATOR_NS" wait --for=condition=Available \
  deployment/cluster-image-registry-operator --timeout=300s
for deployment in image-registry image-api-server; do
  acns wait --for=create "deployment/$deployment" --timeout=600s
  acns wait --for=condition=Available "deployment/$deployment" --timeout=600s
done
acn wait --for=condition=Available apiservice/v1.image.alauda.io --timeout=300s
acn get apiservice v1.image.alauda.io -o json |
  jq -e '.status.conditions // [] | any(.[]; .type == "Available" and .status == "True" and .reason == "Passed")'
registry-migrate run --run-dir "$RUN_DIR" --stage P7-verify --kubeconfig "$KCFG" --approve
registry-migrate verify --run-dir "$RUN_DIR" --kubeconfig "$KCFG"
```

Expected result: Operator, Registry, Image API, and APIService are ready; P7 is `verified` and `verify` exits zero. Confirm Service ports `80→8080`, `443→5000`, and `5000→5000`, Ready endpoints, the new Ingress backend, Config, metadata, and limits. Config remains read-only, pull-Secret management remains Unmanaged, and the Pruner remains suspended. Stop on failure.

## 10. P8-commit: verify business access, then open writes

Use the actual external URL for this cluster, including protocol and port. Do not copy a test environment port to another cluster. A trusted system CA or provider PEM CA is required for TLS acceptance; `curl -k` is only a diagnostic. Set the three test inputs for this cluster before running the probe block.

```bash
export REGISTRY_URL="${REGISTRY_URL:?set the actual external Registry URL, including scheme and port}"
REGISTRY_HOST="$(jq -er '.discovery.routes[0].hostname' "$RUN_DIR/plan.json")"
jq -ne --arg url "$REGISTRY_URL" --arg host "$REGISTRY_HOST" \
  '($url | capture("^https?://(?<host>[^/:]+)(:[0-9]+)?/?$").host) == $host'
CURL_TLS_ARGS=()
if test -n "$REGISTRY_CA_BUNDLE"; then CURL_TLS_ARGS=(--cacert "$REGISTRY_CA_BUNDLE"); fi
http_code="$(curl -sS "${CURL_TLS_ARGS[@]}" --connect-timeout 10 --max-time 20 \
  -o /dev/null -w '%{http_code}' "$REGISTRY_URL/v2/")"
case "$http_code" in 200|401|403) echo "Registry reachable: HTTP $http_code" ;; *) echo "unexpected HTTP $http_code"; exit 1 ;; esac
export TEST_NS="${TEST_NS:?set a namespace containing a migrated test image}"
export TEST_REPO="${TEST_REPO:?set an isolated namespace/repository:tag for dry-run deletion}"
mkdir -p "$RUN_DIR/verification"

env AC_IMAGE_REGISTRY_MODE=legacy \
  ac --kubeconfig "$KCFG" --context "$CTX" get images -n "$TEST_NS" -o json \
  --registry-url "$REGISTRY_URL" | tee "$RUN_DIR/verification/legacy-images.json"
env AC_IMAGE_REGISTRY_MODE=modern \
  ac --kubeconfig "$KCFG" --context "$CTX" get images -o json \
  | tee "$RUN_DIR/verification/modern-images.json"
env AC_IMAGE_REGISTRY_MODE=legacy \
  ac --kubeconfig "$KCFG" --context "$CTX" delete images \
  --repo "$TEST_REPO" --registry-url "$REGISTRY_URL"
env AC_IMAGE_REGISTRY_MODE=modern \
  ac --kubeconfig "$KCFG" --context "$CTX" delete images --repo "$TEST_REPO"
```

Expected result: anonymous `/v2/` 401/403 proves only entry-point reachability; authenticated legacy and modern queries succeed, and both delete commands remain dry-run. The legacy view lists repository/tag data; the modern view uses ImageDigest/ImageStream data. Do not compare row counts as proof of completeness.

Create a disposable test Pod with `imagePullPolicy=Always` using the original image reference, ServiceAccount and Secret. Verify pulls through the original `:80`, `:443`, and `:5000` paths and the external host as applicable. Record the Pod, digest, query output, and pull result. Do not perform a positive push before P8.

After the business checks pass and an administrator approves the cutover:

```bash
jq --arg actor "$ACTOR" --arg at "$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
  '{version:"v1",runID:.runID,planDigest:.digest,observedAt:$at,actor:$actor,commitApproved:true,businessProbeVerified:true,pullSecretHandoffVerified:true}' \
  "$RUN_DIR/plan.json" > "$RUN_DIR/commit-approval.json"
registry-migrate run --run-dir "$RUN_DIR" --stage P8-commit \
  --evidence-file "$RUN_DIR/commit-approval.json" --kubeconfig "$KCFG" --approve
acn get config.imageregistry.operator.alauda.io cluster -o json |
  jq -e '.spec.readOnly == false and .spec.imagePullSecret.managementState == "Managed"'
acn get imagepruner.imageregistry.operator.alauda.io cluster -o json | jq -e '
  .metadata.annotations["registry-migrate.original-suspend"] as $original |
  ($original == "true" or $original == "false") and (.spec.suspend == ($original == "true"))'
registry-migrate verify --run-dir "$RUN_DIR" --kubeconfig "$KCFG"
registry-migrate report --run-dir "$RUN_DIR"
```

Expected result: `state=committed`; Config is writable, pull-Secret management is Managed, and the Pruner has its recorded original suspension value. After Operator reconciliation, use an approved OCI client to push and pull one disposable repository and retain that output. If a failure occurs now, the write transition has already been committed; do not assume read-only state.

## Appendix: S3 access, retries, exceptions, and recovery

### S3 available only inside the cluster

```bash
ac --kubeconfig "/path/to/business.kubeconfig" --context "actual-context" \
  -n minio-system port-forward service/minio 19000:9000
```

In the original terminal:

```bash
curl --fail --connect-timeout 5 --max-time 10 \
  http://127.0.0.1:19000/minio/health/live
S3_ARGS=(--s3-endpoint http://127.0.0.1:19000)
```

The override changes only the P3 transport address; the source endpoint remains in the plan/snapshot and is not replaced in the target Config. Rebuild a broken tunnel and retry the same run. An HTTPS tunnel still uses `https://`; port forwarding does not convert the protocol.

### Exceptions and recovery

- **Force writer fence:** after an administrator accepts the consistency risk, set `FORCE_ARGS=(--force)` before P1/P2/P3/P4/P6. It cannot bypass API, UID, S3, metadata, or stage checks, and never bypasses the new Operator pause in P4/P6.
- **Skip S3 verification:** set `P3_PROTECTION=(--skip-s3-backup-verification)` only when the administrator accepts that no S3 recovery point was established.
- **Nested test residue:** add `--skip-nested-repositories` to P3 only for approved historical test residue. Review `legacy-metadata-report.json`.
- **Original 4.3 ac:** it has no `set-registry-mode`; use `--registry-url`, `--kubeconfig`, and `--context` for a legacy query. The full permission/pagination matrix belongs to the platform’s separate compatibility acceptance record, not to the production migration window.

If the Bash terminal exits, export the original absolute run directory and run Section 0 again:

```bash
export RUN_DIR="/absolute/path/to/registry-migrate-runs/original-run-id"
```

Section 0 restores the original run ID, scope, and discovered Deployments. Re-select S3, force, and P3 protection arrays. Do not create a new run or repeat completed manual uninstall/Ingress deletion steps.

The tool is idempotent within one run: completed Secrets, metadata, limits, and checks are skipped or revalidated. Preserve plan, journal, backups, inventory, snapshot, evidence, and verification output. P3’s protection state is immutable; adding proof later does not change a run that originally skipped verification.

For recovery:

```bash
registry-migrate rollback --run-dir "$RUN_DIR" --kubeconfig "$KCFG" --approve
registry-migrate report --run-dir "$RUN_DIR"
```

`rollback` records a manual recovery request and protects source data. It does not reinstall the old chart, recreate an original-UID Secret, delete Registry v2 resources, or restore S3 objects. Before chart removal, restore old replicas, Pruner/platform state, credentials, and chart configuration from the saved materials. After chart removal, stop new Registry writes and reconciliation first, then manually restore chart/platform configuration, credentials, and S3 access. After P8, account for new images and credential rotation; do not point the same S3 writer back at the legacy Registry without a controlled recovery plan. After a real recovery, start a new run ID and do not edit plan/journal to bypass identity drift.
